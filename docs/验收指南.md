# MICA 验收指南（给你自己验）

> 目标：**不用我在场**，你 5 分钟内能判断"能不能用、哪里坏了"。

## 一、1 分钟自检（推荐先跑）

在项目根目录 `D:\Desktop\DSH\MICA` 打开 PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\selfcheck.ps1
```

它会依次检查并打印 PASS/FAIL：

| 检查 | 期望 | 说明 |
|---|---|---|
| 环境自检 (doctor) | PASS | 数据目录/日志/磁盘/WebView2/Java/网络 |
| GUI 启动并出现窗口 | PASS（首屏通常 1–3s） | 通过计划任务在桌面会话启动，标题应为 MICA |
| 单实例生效 | PASS（进程数=1） | 重复启动不会开第二个窗口 |
| 启动日志写入 | PASS | 生成 `logs/mica.log`，含 `setup 完成` |

结果同时写入 `.data/selfcheck/summary.json`；`doctor` 详情在 `.data/selfcheck/doctor.json`。

## 三、出问题怎么定位

1. **打不开 / 闪退**：看 `%APPDATA%\MICA\logs\mica.log`（若该目录不可写，看 `MICA.exe` 同级的 `MICA-Data\logs\mica.log`）。启动失败会弹窗给出日志路径。
2. **白屏**：`logs\mica.log` 里搜 `主窗口创建失败`；多半是 WebView2 缺失，可安装 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。
3. **下载失败**：设置 → 下载源 切 `BMCLAPI 镜像`；或设置代理 `http://127.0.0.1:7890`。
4. **一键收集**：设置 → 诊断 → 运行自检，把 `logs\diagnostics.txt` 与 `mica.log` 发我即可。

## 四、打包产物自检（C27，不弹窗）

```powershell
powershell -File scripts\verify-web.ps1
```

另可跑 `powershell -File scripts\verify-ipc.ps1` 校验命令边界（前端 camelCase payload）。\n\n会启动**隐藏窗口**加载发布版内嵌前端，检查 `web_url=http://tauri.localhost/` 且 `title=MICA`；若误用 `cargo build --release` 构建，这里会显示 `localhost:5173` 并 FAIL。

## 五、零依赖说明

`release\MICA.exe` 是**单文件便携版**：不依赖 .NET / VC++ 运行库 / Java，也不需要安装。

- 唯一外部运行时是 WebView2：Win11 与正常 Win10 已内置；缺失时 exe 会用内置的 1.8MB 官方引导器**静默安装**（首次约 1 分钟）。
- 目标机器既无网络又无 WebView2 时无法自愈，需要离线安装包（默认不提供，避免 +130MB）。
- 想跳过窗口启动做检查：`powershell -File scripts\selfcheck.ps1 -NoGui`。

## 六、无头 UI 检查（不弹窗、不占屏幕）

```powershell

pnpm preview --port 4173
node scripts\ui-check.mjs
```

输出 **30 条** PASS/FAIL 与 14 张截图（`.data/ui/`），覆盖：首页、搜索/空结果、项目详情、版本向导、CurseForge 空壳、服务端列表/控制台、汉化应用与撤销、诊断面板、浅色主题、1024 窄窗逐页溢出、弹窗越界、运行中服务端状态、减少动态效果、无前端报错。
